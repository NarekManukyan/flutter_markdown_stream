# 0.6.0 plan

Status: draft, 2026-10-26. Branch with the finished fixes:
`fix/sanitizer-and-rendering` (see the `Unreleased` section of CHANGELOG.md).

## Goal

Make `flutter_markdown_stream` the streaming Markdown package people pick
because it renders correctly and stays fast on long answers. 0.6.0 ships the
correctness and rendering fixes already on the branch, plus the features chat
apps ask for most: selection, history messages, safe links, and the
"thinking" / alert blocks that LLM output now uses.

## Version decision

The fixes change visible behaviour (inline cursor, partial links show their
label, per-block structure kept after completion, `restart()` no longer
throws). Under pre-1.0 semver that is a minor bump, so the fixes go out as
**0.6.0**, not 0.5.1.

Two options for timing:

1. **Recommended:** release the fixes as 0.6.0 now, then ship the features
   below as 0.7.0. Users get the bug fixes without waiting on feature work.
2. Hold the fixes and release everything together as 0.6.0.

Milestone A below is the release of the branch. Milestones B–D are the
feature work: 0.7.0 under option 1, or part of 0.6.0 under option 2.

## Milestone B — chat-app essentials

### B1. Static text mode for history messages

Chat screens render past messages with the same widget as the live one.
Today that needs a fake single-event stream.

```dart
MarkdownStream.text(data: message.content, styleSheet: ...);
// or
MarkdownStream(stream: llmStream, initialText: 'Earlier part of the answer');
```

- `MarkdownStream.text` builds the same per-block body with `isDone: true`,
  no smoother, no cursor, no subscription.
- `initialText` seeds the raw buffer (for resumed generations).
- Tests: renders identically to a completed stream of the same text.

### B2. Selection across blocks and messages

- Add `selectionArea: bool` (default `false`). When `true`, wrap the body in a
  `SelectionArea` and pass `selectable: false` to every `MarkdownBody`, so a
  drag can cross block boundaries. `SelectableText` per block cannot do that.
- Copy keeps paragraph breaks between blocks. flutter_markdown_plus has an
  open bug where multi-block copy loses separators (issue #146), so add a
  `SelectionContainer` per block that appends `\n\n` on copy, or contribute
  the fix upstream.
- Optional "copy as Markdown": map the selected plain text back to the raw
  buffer so a copy keeps `**`, links and code fences. Stretch goal; skip if it
  costs more than a few days.
- Benchmark to beat: `flutter_md`'s `MarkdownSelectionController`.

### B3. Safe links and images

- `linkPolicy: LinkPolicy` with defaults that allow `http`, `https`, `mailto`
  and block everything else (`javascript:`, `data:`, `file:`, custom schemes
  unless allowed).
- Blocked links render as plain text. Blocked images render the alt text.
- `onTapLink` stays the hook for a confirm dialog; document the pattern.
- Same idea as Vercel streamdown's `rehype-harden`. LLM output is untrusted
  input, so this should default to on.

### B4. "Thinking" and tool-call blocks

Models stream `<think>…</think>` and tool-call markers before the answer.

- Block syntax for `<think>` / `<thinking>` that produces a `think` element,
  rendered by a default collapsible `ThinkingBlock` (collapsed when done,
  open and streaming while active), replaceable through `builders['think']`.
- Generic hook: `customBlocks: {'tool_call': builder}` for any
  `<tag>…</tag>` pair, with the sanitizer hiding a half-typed opening tag.
- The sanitizer needs to treat an open `<think>` like an open fence: close it
  synthetically and skip inline balancing inside.

### B5. GitHub alerts and footnotes

- `> [!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]`, `[!CAUTION]` as a block
  syntax with a default `AlertBlock` widget (icon + tinted border), themable.
- Footnotes are already parsed by `package:markdown` GFM; add tappable
  references (`onTapFootnote`) and make sure the splitter rule for
  definitions (one block) still keeps per-frame cost acceptable. If not,
  parse definitions separately and inject them into each block's document.

## Milestone C — performance and polish

### C1. Benchmark suite

- `benchmark/` with a 50 KB response (prose, lists, tables, code, math)
  replayed token by token. Report frame build time p50/p95 and total parse
  time for: no incremental, incremental, word fade.
- Publish numbers in the README. Competitors (`flutter_md`, `streamdown`)
  advertise this way.

### C2. Sanitizer cost on long texts

The sanitizer still splits the whole text into lines to track fences on every
tick. Cache the fence state at the last settled block boundary (the splitter
already knows it) and only scan from there. Target: sanitize cost independent
of the settled prefix's length.

That still rescans the whole unfinished block each tick, so one long paragraph
or code block stays O(block length) per tick. If benchmarks show that matters,
add a scan cursor that keeps the fence, code-span and delimiter state at the
previous end of text and resumes from there when the text only grew.

### C3. Time-based word fade

The current fade is position-based: a new word appears at 15% opacity
immediately. Add `WordFadeMode.time` where each word animates from 0 to 1 over
`wordFadeDuration` from the moment it appears, driven by one ticker per tail
paragraph. Keep position-based as the default until the time mode is
benchmarked.

### C4. Wide content

- Tables: horizontal scroll by default, opt-in `tableColumnMaxWidth`.
- Display math: horizontal scroll wrapper in `LaTeXElementBuilder` (long
  equations overflow; a top complaint in gpt_markdown).

### C5. Single `~` strikethrough

`package:markdown` GFM treats a single `~` as strikethrough, so `20~25 and
30~40` strikes "25 and 30". Escape a single `~` between digits in the
sanitizer (same as remend), and do the same on the final text.

| Package | Content |
| --- | --- |

versioned independently.
